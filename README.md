Task Manager — Приложение для управления задачами
Full-stack приложение (панель задач) с разделением доступа по пользователям. Построено на стеке: React (Frontend), Node.js / Express (Backend) и PostgreSQL (Database).

Описание структуры файлов проекта
1. Серверная часть (Backend)
.env — Файл конфигурации переменных окружения. Хранит конфиденциальные данные: настройки подключения к базе данных PostgreSQL (пользователь, хост, имя БД, пароль, порт) и секретный ключ JWT_SECRET для подписи токенов.

server.js — Главная точка входа бэкенд-сервера. Подключает конфигурацию переменных окружения .env по абсолютному пути, выполняет первичную тестовую проверку соединения с базой данных PostgreSQL (тестовый запрос SELECT NOW()) через пул соединений и запускает веб-сервер на хосте 0.0.0.0 и указанном порту (по умолчанию 5000).

app.js — Модуль инициализации и настройки инстанса Express-приложения. Подключает глобальные промежуточные ПО (cors для обработки кросс-доменных запросов и express.json для парсинга входящего тела запросов в формате JSON), монтирует корневые маршрутизаторы бизнес-модулей (/tasks, /users, /auth) и регистрирует финальный централизованный слой обработки ошибок.

role.middleware.js — Промежуточное ПО для разграничения прав доступа на основе ролей пользователей (RBAC). Извлекает и верифицирует JWT-токен из заголовков запроса, парсит массив ролей текущего пользователя и проверяет его на соответствие списку разрешенных ролей для конкретного эндпоинта. В случае отсутствия необходимых привилегий или токена блокирует выполнение запроса с кодом 403 Forbidden.

error.middleware.js — Глобальное промежуточное ПО для централизованной обработки ошибок Express-сервера. Перехватывает любые невыловленные исключения, возникающие на уровне контроллеров или сервисов, логирует стек ошибки в консоль сервера и отправляет клиенту стандартизированный JSON-ответ с соответствующим HTTP-статусом (по умолчанию 500 Internal Server Error) и сообщением об ошибке.

pool.js — Модуль инициализации пула соединений с PostgreSQL с использованием библиотеки pg. Автоматически считывает настройки из .env и приводит пароль к строковому типу во избежание сбоев авторизации.

Schema.sql — SQL-скрипт для развертывания структуры базы данных. Создает таблицы users (хранение данных учетных записей, хэшей паролей и ролей) и tasks (хранение задач с привязкой к конкретному user_id через внешний ключ с каскадным удалением).

auth.middleware.js — Промежуточное ПО (middleware) для защиты маршрутов сервера. Извлекает JWT-токен из заголовка Authorization, проверяет его валидность с помощью секретного ключа и записывает данные авторизованного пользователя в объект запроса (req.user).

auth.controller.js — Контроллер аутентификации. Содержит логику регистрации пользователей (с хэшированием паролей через bcryptjs), логику входа (проверка пароля через bcrypt.compare и генерация Access Token со сроком действия 24 часа) и управление списком пользователей.

auth.routes.js — Маршрутизатор для эндпоинтов аутентификации. Перенаправляет запросы /registration, /login и /users на соответствующие методы контроллера.

user.model.js — Уровень доступа к данным (DAO) для пользователей. Содержит чистые SQL-запросы к базе данных для создания, удаления, обновления профиля и поиска пользователя по адресу электронной почты.

user.service.js — Сервисный слой бизнес-логики пользователей. Отвечает за валидацию входящих данных (проверка обязательных полей, ограничение длины email до 100 символов, длины имени до 50 символов) перед вызовом методов модели.

user.controller.js — Контроллер для обработки стандартных HTTP-запросов (CRUD) по управлению профилями пользователей.

user.routes.js — Маршрутизатор путей API для сущности пользователя (/, /:id).

task.model.js — Уровень доступа к данным для задач. Выполняет SQL-запросы на добавление новой задачи, выборку задач текущего авторизованного пользователя (SELECT ... WHERE user_id = $1), а также обновление и удаление записей.

task.service.js — Сервисный слой бизнес-логики задач. Валидирует длину описания (не более 500 символов) и осуществляет строгую проверку прав доступа: пользователь может изменять или удалять только те задачи, у которых user_id совпадает с его собственным ID из JWT-токена.

task.controller.js — Контроллер обработки HTTP-запросов для управления задачами. Связывает middleware авторизации, извлекает ID пользователя из токена и передает данные в сервис.

task.routes.js — Маршрутизатор для управления задачами. Все эндпоинты (POST /, GET /, GET /:task_id, PUT /:task_id, DELETE /:task_id) полностью закрыты с помощью authMiddleware.

2. Клиентская часть (Frontend / React)
index.html — Главный HTML-шаблон клиентской части приложения. Служит базовым статическим каркасом для SPA (Single Page Application): настраивает мета-теги, кодировку, адаптивный viewport, иконки, заголовок вкладки браузера и содержит единственный корневой элемент контейнера (<div id="root"></div>), в который React-скрипты динамически монтируют всё дерево компонентов.

index.js — Главная точка входа React-приложения. Отвечает за монтирование корневого компонента в DOM-дерево (div#root) и инициализацию React.StrictMode для ведения логов разработки.

App.js — Корневой компонент React-приложения. Конфигурирует маршрутизацию страниц с помощью react-router-dom (маршруты для главной страницы / и страницы авторизации /authentication), а также инициализирует и управляет глобальным состоянием авторизованного пользователя (currentUser).

api.js — Сервисный слой отправки запросов. Обертка над встроенным методом fetch, осуществляющая взаимодействие с API бэкенда. Содержит объект taskAPI (создание, получение, удаление задач) и authAPI (регистрация и авторизация на сервере), автоматически внедряя JWT-токен из localStorage в HTTP-заголовки запросов.

AuthPage.js — Компонент-страница аутентификации. Выступает в качестве визуального каркаса экрана авторизации, подключая элементы интерфейса (Header, Footer) и форму.

AuthForm.js — Управляемый компонент формы авторизации. Поддерживает динамическое переключение режимов «Вход» / «Регистрация» внутри одного окна, обрабатывает ввод данных, отправляет запросы к authAPI, сохраняет полученный токен в хранилище браузера и вызывает callback-функцию onLogin для мгновенного обновления интерфейса.

HomePage.js — Компонент главной страницы трекера задач. Связывает воедино глобальные блоки интерфейса, содержит логику сброса токена из localStorage и очистки стейта пользователя при выходе из аккаунта (handleLogout).

MainContent.js — Центральный управляющий компонент интерфейса задач. Отвечает за реактивную загрузку данных с бэкенда через useEffect. Содержит логику сквозной фильтрации списка задач по их статусу и приоритету, а также сортировку по дате создания. Отвечает за сеточную разметку сайдбара и контентной зоны.

TaskForm.js — Управляемая форма для создания новой задачи. Предоставляет поля для ввода названия, описания (с ограничением длины) и выпадающие списки для выбора приоритета и категории.

TaskList.js — Компонент вывода списка задач. Рендерит массив карточек задач, динамически подставляя CSS-классы в зависимости от параметров задачи, и обрабатывает события изменения параметров или удаления.

TaskSort.js — Интерактивный UI-компонент панели фильтрации и сортировки. Содержит группы кнопок для изменения текущих фильтров по статусу (all, new, in_progress, done), приоритету (all, high, middle, low) и направлению сортировки по дате (asc, desc).

TaskStatistics.js — Компонент панели аналитики данных. Агрегирует текущий массив задач, вычисляя общее количество, распределение по статусам и итоговый процент завершенности (completedScore%) с защитой от деления на ноль.

UserProfile.js — Визуальный компонент карточки пользователя в сайдбаре. В зависимости от наличия авторизации выводит либо заглушку для гостя с предложением авторизоваться, либо персональные данные пользователя (Имя, Email, Роль) и системную кнопку «Выйти из аккаунта».

Header.js — Компонент верхней панели (шапки) сайта. Отвечает за рендеринг заголовка приложения («Task Manager») и его базовое позиционирование.

Footer.js — Компонент нижней панели (подвала) сайта. Отображает фиксированный текст авторских прав с привязкой к текущей стилизации.

HomePage.css — Главный файл стилей приложения. Описывает сеточные и позиционные правила (фиксированный сайдбар .left-side шириной 350px, отступы .taskSide), кастомизацию интерактивных элементов управления, полей ввода и адаптивный дизайн.


Инструкция по развертыванию и проверке работоспособности
Для запуска проекта на локальной машине необходимы установленные компоненты: Node.js (версии 16 и выше) и СУБД PostgreSQL.

Шаг 1: Подготовка базы данных
Запустите консоль PostgreSQL (psql) или воспользуйтесь графическим клиентом (например, pgAdmin).

Создайте новую базу данных:

SQL
CREATE DATABASE task_manager;
Подключитесь к созданной базе данных и выполните скрипт из файла Schema.sql для создания структуры таблиц.

Шаг 2: Настройка конфигурации бэкенда
В корневом каталоге серверной части проверьте или создайте файл .env. Убедитесь, что параметры подключения соответствуют вашей локальной конфигурации PostgreSQL:

Фрагмент кода
DB_USER=postgres
DB_HOST=localhost
DB_NAME=task_manager
DB_PASSWORD=ваш_пароль_от_субд
DB_PORT=5432
PORT=5000
JWT_SECRET=произвольный_секретный_ключ_для_токенов
Шаг 3: Запуск серверной части (Backend)
Откройте терминал в папке проекта (где находятся серверные файлы).

Установите необходимые пакеты (express, pg, bcryptjs, jsonwebtoken, dotenv):

Bash
npm install
Запустите сервер:

Bash
node index.js
(Или используйте команду npm run dev / node app.js в зависимости от точки входа вашего package.json). При старте в консоль выведутся отладочные логи пула базы данных, подтверждающие успешное чтение пароля. Сервер начнет прослушивание порта 5000.

Шаг 4: Запуск клиентской части (Frontend)
Откройте второй терминал и перейдите в каталог с клиентским приложением React.

Установите зависимости проекта (react, react-router-dom и др.):

Bash
npm install
Запустите среду разработки React:

Bash
npm start
После компиляции приложение автоматически откроется в браузере по адресу http://localhost:3000.

Шаг 5: Проверка функционала (Сценарий тестирования)
Чтобы убедиться в полной работоспособности всех компонентов, выполните следующие действия в интерфейсе приложения:

Регистрация пользователя: Нажмите на ссылку «Вход» для перехода на страницу аутентификации. Выберите вкладку «Регистрация», заполните поля (Имя, Почта, Пароль) и нажмите «Создать аккаунт». Форма автоматически переключит режим на «Вход».

Авторизация: Введите данные только что зарегистрированного пользователя. После успешной проверки сервер выдаст JWT-токен, и клиент перенаправит вас на главную страницу /.

Создание задачи: В форме «Добавить задачу» введите корректное название и описание. Выберите приоритет (например, «Высокий») и нажмите кнопку добавления. Задача мгновенно отобразится в правой части экрана в списке задач.

Изменение параметров: В карточке созданной задачи измените приоритет в выпадающем списке или переведите статус задачи в «В процессе» / «Выполнено». Страница должна корректно обновить интерфейс, отправив соответствующий PUT-запрос к API.

Фильтрация и сортировка: Добавьте еще 2–3 задачи с разными приоритетами. Проверьте работу блока сортировки и фильтрации в верхней части списка задач — карточки должны мгновенно перестраиваться под выбранные условия.

Выход: Нажмите кнопку «Выход». Сессия сбросится, очищая данные пользователя из состояния приложения.
