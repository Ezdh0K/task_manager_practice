# Task Manager — Приложение для управления задачами

Full-stack веб-приложение (интерактивная панель задач) с разграничением прав доступа на основе ролей (**RBAC**). Проект разработан в рамках образовательной практики и представляет собой удобный таск-трекер с возможностью распределения приоритетов, фильтрации и глубокого контроля доступа к данным.

---

## Технологический стек

* **Frontend:** React, React Router DOM, HTML5/CSS3 (Grid & Flexbox), Сборка/Запуск через CRA.
* **Backend:** Node.js, Express.js, JWT (JsonWebToken), Bcryptjs (хеширование паролей).
* **Database:** PostgreSQL (библиотека `pg` для управления пулом соединений).

## Структура файлов проекта

### Серверная часть (Backend)

```text
backend/
├── db/
│   ├── pool.js              # Инициализация пула соединений с PostgreSQL
│   └── Schema.sql           # SQL-скрипт развертывания структуры базы данных
├── middlewares/
│   ├── auth.middleware.js   # Защита маршрутов, проверка валидности JWT
│   ├── role.middleware.js   # Разграничение прав доступа на основе ролей (RBAC)
│   └── error.middleware.js  # Централизованная обработка серверных ошибок
├── modules/
│   ├── auth/
│   │   ├── auth.controller.js
│   │   └── auth.routes.js
│   ├── users/
│   │   ├── user.model.js
│   │   ├── user.service.js
│   │   ├── user.controller.js
│   │   └── user.routes.js
│   └── tasks/
│       ├── task.model.js
│       ├── task.service.js
│       ├── task.controller.js
│       └── task.routes.js
├── .env                     # Файл конфигурации переменных окружения
├── app.js                   # Настройка инстанса Express и промежуточного ПО
└── server.js                # Главная точка входа, проверка БД и запуск сервера
            

```

| Файл / Модуль | Описание функционала |
| --- | --- |
| **.env** | Хранит конфиденциальные данные: доступы к PostgreSQL и секретный ключ `JWT_SECRET`. |
| **server.js** | Точка входа бэкенда. Подключает `.env` по абсолютному пути, тестирует подключение к БД (`SELECT NOW()`) и слушает хост `0.0.0.0` (порт `5000`). |
| **app.js** | Инициализация Express, подключение глобальных middleware (`cors`, `express.json`), монтирование маршрутов (`/tasks`, `/users`, `/auth`) и обработка ошибок. |
| **role.middleware.js** | Слой RBAC. Верифицирует токен, парсит роли пользователя и блокирует доступ (код `403 Forbidden`), если у пользователя нет необходимых прав. |
| **error.middleware.js** | Централизованный перехватчик исключений. Логирует ошибки в консоль сервера и отправляет клиенту стандартизированный JSON-ответ. |
| **pool.js** | Модуль пула соединений через `pg`. Автоматически преобразует пароль из `.env` к строгому строковому типу во избежание сбоев. |
| **Schema.sql** | Структура базы данных: таблицы `users` (аккаунты, хэши, роли) и `tasks` (задачи с привязкой к `user_id` и каскадным удалением). |
| **auth.middleware.js** | Извлекает токен из заголовка `Authorization`, проверяет его и записывает данные пользователя в `req.user`. |
| **auth.controller.js** | Логика регистрации (хэширование паролей через `bcryptjs`) и авторизации (выпуск Access Token на 24 часа). |
| **user.model.js** | Слой доступа к данным (DAO) для пользователей. Чистые SQL-запросы без тяжелых ORM. |
| **user.service.js** | Бизнес-логика пользователей. Отвечает за валидацию данных перед вызовом модели (ограничения длины email, имени). |
| **task.model.js** | DAO для управления задачами. Выполняет SQL-запросы на выборку задач текущего пользователя, создание, обновление и удаление. |
| **task.service.js** | Бизнес-логика задач. Проверяет ограничения (описание до 500 символов) и строго контролирует права: изменять/удалять можно только свои задачи. |

## Инструкция по развертыванию локально

### Требования к окружению

* **Node.js** (версии 16 и выше)
* СУБД **PostgreSQL**

### Шаг 1: Подготовка базы данных

1. Откройте терминал СУБД (psql) или графический менеджер (pgAdmin / DBeaver).
2. Создайте целевую базу данных:
```sql
CREATE DATABASE task_manager;

```


3. Подключитесь к созданной базе данных и примените SQL-скрипт из файла `Schema.sql` для генерации таблиц `users` и `tasks`.

### Шаг 2: Настройка переменных окружения (.env)

В корневой папке **серверной части (backend)** создайте файл `.env` и внесите в него параметры конфигурации:

```env
DB_USER=postgres
DB_HOST=localhost
DB_NAME=task_manager
DB_PASSWORD=ваш_пароль_от_субд
DB_PORT=5432
PORT=5000
JWT_SECRET=super_secret_key_12345

```

### Шаг 3: Запуск ИИ-микросервиса (Python)
cd service
1. Создание и активация окружения
python -m venv .venv
source .venv/bin/activate # Для Windows: .venv\Scripts\activate

2. Установка зависимостей
pip install fastapi uvicorn pymorphy3 pymorphy3-dicts-ru pydantic

3. Запуск (порт 8000 по умолчанию)
uvicorn main:app --reload

### Шаг 4: Запуск бэкенда (Backend)

1. Откройте терминал в каталоге серверной части проекта.
2. Установите зависимости:
```bash
npm install

```


3. Запустите сервер:
```bash
npm run server

```


*При успешном старте в консоль выведутся отладочные логи пула БД, подтверждающие подключение, а сервер начнет слушать порт 5000.*

### Шаг 5: Запуск фронтенда (Frontend)

1. Откройте второй терминал и перейдите в папку с клиентским приложением React.
2. Установите зависимости:
```bash
npm install

```


3. *(Для Windows-пользователей при ошибке политик выполнения скриптов в терминале)*:
```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy RemoteSigned

```


4. Запустите среду разработки:
```bash
npm start

```


*Приложение автоматически откроется в браузере по адресу `http://localhost:3000`.*

## Сценарий сквозного тестирования функционала

Для проверки полной работоспособности цепочки Frontend ↔ Backend ↔ PostgreSQL выполните следующий чек-лист:

1. **Регистрация аккаунта:**
* Перейдите на страницу авторизации (кнопка "Вход").
* Откройте вкладку «Регистрация», введите имя, email и пароль. Нажмите «Создать аккаунт».
* Форма должна автоматически переключиться в режим «Вход».


2. **Аутентификация:**
* Введите логин и пароль только что созданного пользователя.
* После успешного ответа сервера токен сохранится в `localStorage`, а интерфейс перенаправит вас на главную страницу `/`, отобразив профиль в сайдбаре.


3. **Добавление задачи:**
* В форме «Добавить задачу» заполните Название, Описание и выберите приоритет.
* Нажмите «Добавить задачу» — новая карточка должна мгновенно появиться в списке справа, а в блоке статистики обновятся счетчики.
* В форме создания задачи введите название: «Подготовить презентацию для клиента по работе» и оставьте поля категории/приоритета пустыми или выберите "Авто".
* Нажмите добавить. Node.js отправит запрос в Python, pymorphy3 разберет слова, приведет их к нормальной форме (презентация, клиент, работа), сопоставит со словарем в keywords.py и автоматически выставит категорию work и приоритет high. Задача появится на доске уже размеченной.


4. **Редактирование состояния (PUT-запросы):**
* В карточке созданной задачи измените статус (например, переведите в "В процессе" или "Выполнено") или смените приоритет в выпадающем списке.
* Интерфейс должен реактивно перекрасить границы и фоны карточки в соответствии со встроенными CSS-переменными.


5. **Фильтрация и сортировка:**
* Создайте еще 2–3 задачи с разными приоритетами и категориями.
* Покликайте по кнопкам фильтров в панели `TaskSort` ("Новые", "В процессе", "Высокий" и т. д.) и проверьте сортировку по дате. Карточки должны мгновенно перестраиваться без перезагрузки страницы.


6. **Безопасность и Логаут:**
* Нажмите кнопку «Выход». Сессия сотрется из `localStorage`, стейт обнулится, а приложение вернет вас в режим гостя, заблокировав отправку данных.
